# HTTP acquisition

Цель: получить содержимое официальных сайтов с соблюдением политики, оставив неизменяемое сырое доказательство.

`http-acquisition/connector-and-worker` — строгие контракты запроса и manifest, включая typed seed-specific robots decision и evidence identity; нормализация URL, проверка публичной адресуемости, robots/sitemap, планирование страниц, условные запросы, ограниченная декомпрессия и один Scrapy-запуск.

Цепочки:

URL источника → политика origins → планирование → один `http_request` артефакт → Scrapy child → 2xx: raw артефакт + acquisition manifest; 304: только манифест с точным прежним входом; 403: policy-blocked; 429: типизированный transient с Retry-After.

Сохранённый route context → robots-запрос → решение в manifest для точного seed URL → page-работа только при typed-разрешении; запрет не создаёт page-работу.

Границы:

- только HTTP(S) канонические URL одобренного origin; DNS-ответы и подключённый адрес обязаны быть глобально маршрутизируемыми;
- userinfo, private/loopback/link-local/reserved, не-HTTP схемы, следование редиректам, cookies, загрузки и неподдерживаемые кодировки отклоняются;
- редиректы фиксируются, но не выполняются; каждый target становится новой работой по политике;
- 403 и 429 не создают браузерную работу;
- закодированный и раскодированный размер ответа имеют отдельные явные лимиты;
- worker не получает учётные данные PostgreSQL или объектного хранилища; транспорт — только `source_connector_sdk`.

Tests: `connectors/official_http/tests`, `apps/http_worker/tests`.

Философия: политика источника проверяется до сети, а не после. Каждый ответ либо доказательство, либо типизированный отказ; молчаливого успеха нет.
