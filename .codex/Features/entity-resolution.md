# Entity resolution

Цель: детерминированно сопоставить кандидатов, построить обратимые кластеры и вынести fail-closed вердикт качества.

`entity-resolution/resolution-and-quality` — контракты батча, точной географической ссылки, ручных решений, признаков пары, disposition, линии кластера, оценки качества и снапшота резолюции; детерминированное блокирование, целочисленные признаки похожести, приоритет disposition, явные ограничения разделения и хост resolution worker; golden-данные как синтетическое доказательство.

Цепочки:

Кандидатный батч + точная ревизия рыночной области → блокирование → признаки пар → disposition → кластеры → оценка качества → resolution snapshot.

Кластер → все применимые правила → `exportEligible` или явные блокирующие issues.

Границы:

- `entity_resolution` — non-source capability и отклоняет source permit;
- пара только по имени никогда не становится `auto_match`;
- fuzzy-пары внутри или на границе Берлина требуют ревью;
- точный телефон/email автоматически сопоставляются только при совместимых видах сущностей и непротиворечивой географии;
- website/address требуют подтверждения по политике;
- явное разделение блокирует прямые и транзитивные склейки;
- идентичность кластера следует только из отсортированных ID участников, разделение и откат воспроизводимы;
- качество стартует заблокированным и становится экспортно-допустимым только при прохождении всех применимых правил;
- география кампании принадлежит `campaign-config`; резолюция потребляет точную ревизию и digest и не пересчитывает покрытие.

Философия: сомнение трактуется как ревью, не как совпадение. Golden-данные — тестовое доказательство и не делают реальную кампанию Берлина запускаемой.
